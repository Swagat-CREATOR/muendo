What Mewndo can and can't undo

Mewndo can undo

  • Changes to files in your protected folders: files an agent (or anyone) deleted, edited, moved or created. Mewndo puts back any saved version, byte for byte, and checks every file it restores.
  • The whole folder, just the files you choose, or a copy into a separate folder.
  • Its own restores: anything a restore replaces goes to Mewndo's trash, and a save point is made first.
  • Changes made while Mewndo was closed, and to the .git folder, so damage to your repository history can be undone too.

Mewndo can't undo

  • Emails or messages an agent sent.
  • Payments or purchases.
  • Changes to websites or online accounts, including cloud services, databases and anything an agent did over the internet.
  • Changes outside your protected folders, anywhere else on this computer.
  • Files Mewndo skipped: files over the size limit (50 MB unless you changed it), files and folders matched by ignore rules (such as node_modules, dist, build, and patterns you added in Settings), and online-only OneDrive files that aren't on this computer.

Good to know

  • Mewndo keeps history for each folder's retention period (30 days unless you changed it). Older save points are removed, and automatic ones may go sooner if storage passes the budget.
  • While a folder can't be found (for example an unplugged drive), changes to it can't be recorded. Its save points are kept, and Mewndo resumes as soon as it's back.
  • After a power cut or system crash, file versions saved in the last few minutes may not have reached the disk. Mewndo checks them at the next start, saves the files again where it can, and tells you if any versions were lost.
  • Which agent made a change is only certain when the agent reports itself (Claude Code with Mewndo's hooks set up). Otherwise Mewndo shows the agent that was running, marked "likely".
  • Stop the agent before undoing, or it may keep changing files while Mewndo puts them back.
